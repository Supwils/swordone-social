# S5 — hygiene: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Remove Mongo leftovers, add NOT VALID foreign keys with an orphan report, make Prettier/knip/mcp-lint CI gates and run e2e in CI, zero agent ResourceWarnings, fix the S4 follow-ups, and consolidate the docs.

**Architecture:** Independent cleanup tasks on disjoint surfaces; the mechanical reformat runs last among code tasks so its diff is pure formatting; docs last.

**Tech Stack:** Express/Drizzle/Postgres/Vitest (server), React/Vite (client), MCP (Node16 ESM), Python/pytest (agent), Playwright (e2e), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-15-s5-hygiene-design.md` — **§10 (binding details from review) overrides §1–§9; every task reads §10 first. Tasks run strictly in order.**

## Global Constraints

- **NO `git commit`, `git push`, `git stash`, `git checkout -- <file>`, `git reset`, `git clean`.** Leave every change in the working tree.
- **No production access**: no Neon migration or query, no deploy, no calls to `SWIL_URL`. **No manual agent CLI runs at all** (`agent/.env` points at Railway production and wins over the process environment); exercise agent code only in pytest with settings patched.
- The experiment data path is untouched: `agent/tests/unit/golden/cycle_*` and `dream_*` stay byte-identical; no change to post vectors, similarity rows, cycle_run cards, round ids.
- No change to `agent/archive/**`, `agent/agents/**`, `docs/superpowers/**` (history), the frozen pre-registration files. Never touch `agent/Untitled`, `agent/archive/era-2/agents/fenziys/Untitled`, `.env`, `api_key.txt`.
- Generated contract copies (`client/src/contract/`, `mcp/src/contract/`, `agent/tests/contract/`) are only written by `npm --prefix server run contract:sync`.
- Coverage floors unchanged (never lower). Server: no `any`, no `console.log`. Dependencies added only where the spec names them; note each in the report (the commit body needs the reason).
- Each task ends with the touched packages' checks green; the last task ends with `npm run ci:check` green from the repo root.

## Review Focus

1. A test seed or code path that inserts a child row before its parent, or hard-deletes a parent → FK violation surfaces as a failing test, and the fix is in code, not by dropping the FK.
2. `db:orphans` on a DB with one orphan per constraint → reports each and exits 1; on a clean DB exits 0; it never writes.
3. Prettier reformat → no non-formatting change (`git diff -w` review), generated contract copies unchanged, `contract:check` green.
4. A new unclosed sqlite connection in an agent test → suite fails.
5. `POST /posts` echo → response has `echoOf` equal to what `GET /posts/:id` returns.
